# AGENTS.md

Guidance for AI coding agents (and contributors) working in this repository.
This is the source for Marcelo S. Perlin's personal academic website: a
server-rendered **Flask** app where content lives in JSON files and the code
only shapes how it is displayed.

## Quick start

```bash
uv sync              # create .venv and install from uv.lock
uv run python app.py # dev server at http://127.0.0.1:5000 (debug reload on)
uv run pytest        # smoke-test every route
```

`uv` (with `pyproject.toml` + `uv.lock`) is the source of truth for
dependencies. `requirements.txt` exists only as a plain-`pip` convenience.
`python >= 3.10` is required; production runs `python:3.13-slim`.

## Core principle: content is data, not code

The site is deliberately data-driven. **Routine content updates are done by
editing JSON in `data/`, never by editing HTML templates.** Do not hardcode
content into templates or `app.py`; extend the JSON schema and template instead.

```
app.py               all routing + data loading + SEO/citation helpers (single file)
data/                JSON content (publications, books, news, slides, awards,
                     datasets, code, stats, about/research/press/consulting)
templates/           Jinja2 HTML templates
static/              CSS, JS, fonts, images (all self-hosted, no CDNs)
books_rendered/      rendered bookdown HTML books, served under /books/<name>/
scripts/             maintenance scripts (stats, image optimization, publications sync)
tests/               pytest smoke tests
```

## Data directory conventions

- `load_data_from_folder(path)` reads every `*.json` in a folder (one level of
  nested folders for `publications`, `books`, `awards`, `slides`, `news`,
  `datasets`, `code/r`, `code/python`). The **filename stem** becomes the
  `filename_stem` field and, for publications, the URL slug (via `slugify`).
  Slugs must be unique — the test suite asserts this.
- Publications, books, datasets and news are sorted newest-first by `year` /
  `date` at request time.
- `data/publications-review/` holds preprints / software / DOI-less works that
  were found automatically but are **not published**. Move a file into
  `data/publications/` to publish it. Never publish from `-review` directly.
- `data/stats/*.json` are machine-generated (Google Scholar, Amazon, downloads,
  GitHub). Do not hand-edit them; re-run the relevant script in `scripts/`.

### Field notes (important, easy to get wrong)

- Publication `year` is a **string** (`"2026"`); book `year` is an **int**
  (`2024`). Sorting in `app.py` calls `int(x.get('year', 0))` — keep these
  types consistent.
- Publication citations are generated on the fly: BibTeX (`bibtex_for`), RIS,
  APA/ABNT/Chicago (`format_*`). A publication's slug and citation key come from
  `filename_stem` / `title`, so rename a publication file deliberately.
- `link` (DOI/publisher URL) and `doi` are reconciled in `get_publications()`;
  a bare DOI is extracted from `link` when `doi` is absent.
- News items may set `publication_slugs` (array) or `paper_link` to associate
  coverage with a publication; `pdf` paths point into `data/news/pdfs/`.

## Frontend constraints

- Everything is server-rendered; JavaScript is progressive enhancement only and
  must stay optional (content remains visible with JS disabled).
- **No third-party CDNs.** All CSS/JS/fonts are self-hosted from `static/`.
  Chart.js lives in `static/js/vendor/`.
- Reference static assets through the `static_url('path')` template global, which
  appends a `?v=<mtime>` cache-buster. Never hardcode `/static/...` URLs in
  templates.
- A strict **Content-Security-Policy** with a per-request nonce is set in
  `add_security_headers()` (`app.py`). Any inline `<script>` must use the
  `csp_nonce` context variable; `<style>` is allowed inline, `script-src` is
  not. New JS goes in `static/js/main.js`.
- Images: originals in `static/img/`, optimized WebP derivatives in
  `static/img/opt/` generated by `python scripts/optimize_images.py` (needs
  ImageMagick `magick`). Templates use `opt_url` and `img_dims()`.

## Invariants to preserve

- **Path traversal**: any route serving files from a folder (`serve_book`,
  `serve_slide`, `serve_news_pdf`) must route through `_safe_subdirectory()`.
  Never build a `send_from_directory` target by string-concatenating user input.
- **Security headers** are applied globally in `add_security_headers`; HTML gets
  `no-cache` + CSP, feeds get `public, max-age=600`. Preserve this when adding
  routes.
- **Publications are cached** in `_PUBLICATION_CACHE` once per process. In dev
  with debug reload this is fine; in a long-lived process, edits to
  `data/publications/` require a restart.
- `/site-log` reads recent commits from the GitHub API in production (`.git` is
  excluded from the Docker image and `python:3.13-slim` has no git binary),
  falling back to local `git log` in dev. Tests monkeypatch these calls — keep
  them network-free by default.
- Sitemap, feeds (`/feed.xml`, `/publications/feed.xml`, `/feed.json`),
  `/llms.txt`, `/search`, JSON endpoints (`/publications.json`, `/code.json`,
  `/data.json`, `/books.json`) are all generated dynamically from the same
  `data/` sources. Do not hand-maintain generated files.

## Common tasks

| Task | Do |
| --- | --- |
| Add a publication | Add `data/publications/<stem>.json` (copy an existing file for the schema) |
| Add news | Add `data/news/<stem>.json` with `date` as `YYYY-MM-DD` |
| Update "About me" | Edit `data/about.json` |
| Update scholar stats | `uv run --group stats python scripts/run_scholarly.py` |
| Update download/GitHub stats | `uv run python scripts/update_{cran,pypi,github}_*.py` |
| Add/replace an image | Drop in `static/img/`, then `uv run python scripts/optimize_images.py` |
| Add a Python package | Add `data/code/python/<name>.json` (see README §8) |
| Sync pubs from ORCID/Crossref | `uv run python scripts/update_publications.py` |

## Testing & CI

- `uv run pytest` runs smoke tests covering every public route, per-publication
  detail pages and `.bib` downloads, RSS/sitemap validity, and security/caching
  headers. It runs on every push/PR via `.github/workflows/tests.yml`.
- When you add a route, add it to the `skip` sets in `test_all_static_routes_render`
  only if it is not a plain GET page; otherwise it will be auto-tested.
- Weekly GitHub Actions keep `data/stats/` and publications fresh
  (`.github/workflows/update_*.yml`).

## Deployment

Cloud Run via the `Dockerfile`; build is `uv sync --frozen --no-dev` and the
server is `gunicorn --workers 1 --threads 8 app:app`. The `stats` dependency
group is intentionally excluded from the production image. See README for the
`gcloud run deploy` flow.
